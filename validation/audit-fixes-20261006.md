## 实际运行验证与边界

- 在当前已安装 Codex Desktop 上，对发起本次修复的原对话做了一次 owner/runtime 只读查询：owner 存在，返回 `active/openai`，墙钟约 0.0903 秒、CPU 约 0.0129 秒。未发送测试消息或触发模型执行。
- 一个空队列、无团队和无预算的隔离 worker 真实启动，启动阶段登记 PID，经本地端点停止后正常退出。该测试不代表在大文件、SQLite 长时间锁竞争或磁盘故障中的最坏停止时延。
- 维护方的本机既有实例已同步共同运行模块。更新前保留了私有回退快照，先在其数据库副本上迁移，再在实例中载入并读取状态；完整性检查通过，投影迁移前后业务表内容一致。私有角色、身份卡、初始化绑定和账本未被公开配置替换。其他团队实例未更改。
- 正式后台 worker 没有启动；旧账本中的 worker 心跳仅是历史登记。未运行长时压力、设备温度/功耗观测、真实多角色投递或付费模型验收，不能据此宣称现场持续高 CPU 的归因已完全闭环。
- 修复避免后续漏计；未对已经丢失或归属不明的历史用量自动重算。原有 gap 保留，不能把历史覆盖度称为已修复完整。跨 root 回合复用子线程的协议行为仍待独立核实，本轮未据假设改变归属规则。
- 源码修复与验证证据随本次 Git 提交发布到共享仓库；部署状态以本节实际运行记录为准。
